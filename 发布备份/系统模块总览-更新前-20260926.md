## 1. 系统总览

项目目标是在 Tang Mega 60K + NEO Dock 上实现 FPGA 原生实时多音色电子乐器：输入事件驱动硬件合成，电脑用于开发、参考模型和观测，不承担正式演奏时的音频合成。

![高云杯电子琴目标系统框图](gaoyun-architecture-20260919.jpg)

> 上图为 2026-09-19 的目标架构图，保留用于说明系统分层。图中“完整多声部待集成”“效果器待集成”等内容仍属目标；键盘现已明确为 MIDIPLUS X4 III，具体接收电路和正式输入引脚仍待确认。当前实现与验收边界以下表和正文为准。

系统分为三层：

1. **上位机与开发工具链**：Python 黄金模型、波表/FCW 生成、音频分析、串口状态工具、RTL 仿真和 Gowin 构建。
2. **FPGA 实时处理**：输入适配、统一事件、缓存/仲裁、声部管理、DDS、ADSR、混音/效果、PCM 和音频串行输出。
3. **板级链路**：MIDI 接收电路、Tang Mega 60K、PT8211-S DAC、NS4263 功放与实际音频输出。

### 1.1 当前正式顶层的实际通路

```text
两颗板载按键（A4 / C5）
  -> button_debouncer（当前默认 3 ms）
  -> button_event_converter（本地 FIFO 默认深度 4）
  -> 64 位 performance_event_t
  -> simple_voice（单声部占位，内部音高查表 + 256 点正弦表）
  -> 左右相同的 24 位 PCM
  -> 逐帧结果寄存器 + pcm_frame_buffer（代次校验、握手、欠载保持）
  -> i2s_tx（舍入/饱和到 16 位，LSBJ）
  -> PT8211-S -> NS4263 -> 音频输出

I2S 完整帧边界 -> frame_tick -> sample_req -> sample_tick -> 音源推进
SOURCE_MODE=1：固定测试音 -> 同一帧缓存与音频输出通路
uart_tx：当前正式顶层恒为 1，尚不输出状态行
```

源码入口为 `code/rtl/board/electronic_piano_top.sv`。该顶层未例化 MIDI 输入、正式 4 声部管理、ADSR、混音器、延迟效果器或系统 UART 状态发送器。两颗按键能够选两个音高，不代表两个声部可以同时发声。

### 1.2 目标完整通路

```text
X4 III DIN MIDI OUT / 板载按键
  -> 输入适配与本地缓存
  -> 输入仲裁 + 公共事件 FIFO（规范深度 32）
  -> 声部管理（保底 4 复音）
  -> 音高/FCW + DDS/波表
  -> ADSR 与力度/表情映射
  -> 宽位混音 + 饱和限幅 + 可选效果
  -> 24 位 PCM -> 16 位 LSBJ -> DAC/功放

状态计数器 -> UART 状态发送（T025）-> 上位机（T026）
固定 N 声部纯正弦测试 -> FFT 谱峰、活跃声部数、削波证据（T052）
```

#### 七个状态字段的含义

补充日期：2026-09-22；2026-09-25 按 v1.3 更新欠载说明。

`parse_status_line(line) -> StatusSnapshot` 表示：读取一行串口文本、检查格式，再转换为包含七个字段的状态对象。`uint32` 是无符号 32 位整数，取值范围为 0～4,294,967,295。

| 字段 | 含义 | 例子与判断方法 |
|---|---|---|
| `active_voice_count` | 当前活跃声部数，表示多少个声部正在工作。 | 四个音同时发声时可能为 4。松键后如果还在 ADSR 释放阶段，声部可能仍活跃，因此不一定等于按住的琴键数。 |
| `clip_count` | 削波累计次数：混音结果超过允许范围、执行饱和限幅时计数。 | PCM24 最大值为 8388607；若结果为 9000000，会限制到最大值并记录削波。持续增长时应检查声部幅度与混音增益。 |
| `event_fifo_level` | 事件 FIFO 当前积压数量，统计的是演奏事件，不是音频样本。 | 值为 3 表示仍有 3 个事件等待处理，例如 Note On/Off。短暂升高正常，长期接近容量说明处理跟不上。 |
| `event_fifo_high_watermark` | 事件 FIFO 在统计期间达到过的最高水位。 | 当前水位为 0、最高水位为 12，表示现在已处理完，但此前最多积压 12 个事件；可用于评估 FIFO 容量。 |
| `event_fifo_overflow` | 事件 FIFO 溢出计数，记录无法正常接纳事件的异常。 | 正常应为 0。增长可能意味着缓存不足、反压未被遵守或外部输入无法暂停；若丢失 Note Off，可能出现松键后仍响的挂音。 |
| `audio_underrun` | 音频欠载计数：发送端需要新样本时，算法未及时交付。 | 正常应为 0。v1.3/T055 已实现每缺样帧加 1、重复上一组有效样本；首个有效样本前静音不计数。频繁出现需检查处理耗时和 PCM 握手。 |
| `max_processing_cycles` | 统计期间最长一次音频处理耗时，单位为系统时钟周期。 | 50 MHz 下每周期 20 ns；900 周期为 18 μs。48 kHz 每组样本约有 20.83 μs，处理和交付需留有余量。 |

例如，七个字段依次为 `4、0、2、8、0、0、900`，表示当前有 4 个活跃声部，2 个事件等待处理，历史最多积压 8 个事件；未记录削波、事件溢出或音频欠载，最长一次处理耗时为 900 个周期，在 50 MHz 下对应 18 μs。

> 七字段串口协议仍是候选；其中 audio_underrun 已在 v1.3/T055 帧缓存实现为逐缺样帧增加、复位清零、32 位饱和。T025 仍需明确其他字段的统计边界、清零规则，以及活跃声部是否包括释放阶段、削波按声道还是样本组计数、处理耗时起止点。内部已有计数尚未通过正式 UART 上报。

**新增帧级信号与计数解释**

| 名称 | 含义 | 注意事项 |
|---|---|---|
| `sample_req_id` / `pcm_req_id` | 当前请求编号 / 结果回传编号 | 只有当前请求且编号匹配才允许握手；生产者应取消旧结果 |
| `pending_valid` | 一组待边界消费的左右样本已就绪 | 消费前不可覆盖 |
| `audio_frame_count` | 完整左右帧的累计数量 | 每 64 BCLK 一次，不是每次 LRCK 跳变 |
| `pcm_request_count` | 实际发出的计算请求数量 | 计算端不可用时可能少于帧数 |
| `pcm_commit_count` | 成功交付待发送缓存的数量 | 只计 pcm_valid 与 pcm_ready 同时为 1 的握手 |
| `audio_underrun` | 开始有效播放后缺少新样本的帧数 | 首次有效样本前不计，复位清零，最大值饱和 |

| `pa_en` | AB16 | LVCMOS33 / 3.3 V | 低有效功放使能 |
| `uart_tx` | U15 | LVCMOS33 / 3.3 V | 当前正式顶层为空闲高 |

`pa_en=0` 开功放，`pa_en=1` 关功放；当前由 `~rst_sync_n` 驱动。复位/按键为 1.5 V 域，不能把所有 GPIO 都当作 3.3 V。DAC 线路输出不能直接驱动无源扬声器。

### 5.3 外部输入诊断边界

- T053 已实测 V14 为本板 UART RX，按 LVCMOS33 / 3.3 V 配置可接收；但正式 CST 中禁用项尚未解除，不能据诊断结果擅自改正式顶层。
- 板载接口可能持续驱动 V14，外部输入诊断采用 R17；它不是已冻结的正式 MIDI 输入引脚。
- T054 诊断约束采用 R17 输入、R18/T18 回传，3.3 V。V0060 更正了连接器资料：R17 对应 J14 第 5 脚或 J9 第 8 脚；地为 J14 第 12 脚或 J9 第 3/4 脚。**J14 第 11 脚是 5 V，不能当地线。**实物方向与通断仍须核对。
- 本板 J9/J8 不能套用 Digilent 通用 PMOD 排针定义。上述是诊断工程资料，不代表正式 MIDI 光耦链已经上板。
