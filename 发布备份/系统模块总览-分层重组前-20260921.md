## 1. 系统总览

项目目标是在 Tang Mega 60K + NEO Dock 上实现 FPGA 原生实时多音色电子乐器：输入事件驱动硬件合成，电脑用于开发、参考模型和观测，不承担正式演奏时的音频合成。

![高云杯电子琴目标系统框图](gaoyun-architecture-20260919.jpg)

> 上图为 2026-09-19 的目标架构图，保留用于说明系统分层。图中“完整多声部待集成”“效果器待集成”等内容仍属目标；键盘现已明确为 MIDIPLUS X4 III，具体接收电路和正式输入引脚仍待确认。当前实现与验收边界以下表和正文为准。

系统分为三层：

1. **上位机与开发工具链**：Python 黄金模型、波表/FCW 生成、音频分析、串口状态工具、RTL 仿真和 Gowin 构建。
2. **FPGA 实时处理**：输入适配、统一事件、缓存/仲裁、声部管理、DDS、ADSR、混音/效果、PCM 和音频串行输出。
3. **板级链路**：MIDI 接收电路、Tang Mega 60K、PT8211-S DAC、NS4263 功放与实际音频输出。

### 1.1 当前正式顶层的实际通路

```text
两颗板载按键（A4 / C5）
  -> button_debouncer（当前默认 3 ms）
  -> button_event_converter（本地 FIFO 默认深度 4）
  -> 64 位 performance_event_t
  -> simple_voice（单声部占位，内部音高查表 + 256 点正弦表）
  -> 左右相同的 24 位 PCM
  -> i2s_tx（舍入/饱和到 16 位，LSBJ）
  -> PT8211-S -> NS4263 -> 音频输出

SOURCE_MODE=1：固定测试音 -> 同一音频输出通路
uart_tx：当前正式顶层恒为 1，尚不输出状态行
```

源码入口为 `code/rtl/board/electronic_piano_top.sv`。该顶层未例化 MIDI 输入、正式 4 声部管理、ADSR、混音器、延迟效果器或系统 UART 状态发送器。两颗按键能够选两个音高，不代表两个声部可以同时发声。

### 1.2 目标完整通路

```text
X4 III DIN MIDI OUT / 板载按键
  -> 输入适配与本地缓存
  -> 输入仲裁 + 公共事件 FIFO（规范深度 32）
  -> 声部管理（保底 4 复音）
  -> 音高/FCW + DDS/波表
  -> ADSR 与力度/表情映射
  -> 宽位混音 + 饱和限幅 + 可选效果
  -> 24 位 PCM -> 16 位 LSBJ -> DAC/功放

状态计数器 -> UART 状态发送（T025）-> 上位机（T026）
固定 N 声部纯正弦测试 -> FFT 谱峰、活跃声部数、削波证据（T052）
```

## 3. FPGA 实时数字处理链

### 3.1 时钟、复位与采样节拍

| 项目 | 当前定义 |
|---|---|
| 系统时钟 | 板载 50 MHz，`sys_clk`，周期 20 ns |
| 实际复位命名 | 顶层外部 `sys_rst_n`，同步器输出 `rst_sync_n` |
| 复位规则 | 低有效，允许异步拉低，在本时钟域同步释放 |
| 采样节拍 | 48 kHz `sample_tick`，单个 `sys_clk` 周期使能，不是独立时钟 |
| 实现 | `reset_sync.sv`、`sample_tick_gen.sv`、`audio_defs_pkg.sv` |
| 证据 | T019 已完成；V0065 记录公共包、复位、节拍三套自检共 70 项 PASS |

接口文档里的建议复位名称与当前顶层名称不同，接线和代码定位以实际端口为准。音频算法、BCLK 生成均工作在系统时钟下，不把普通逻辑生成的节拍作为内部时钟。

### 3.2 输入适配与 X4 III 交互方案

**板载按键：**`button_debouncer` 和 `button_event_converter` 已集成；`key_n[0]`=AB13 对应 A4（69），`key_n[1]`=Y12 对应 C5（72）。AA13 是复位，不作为琴键。当前默认去抖为 150000 个 50 MHz 周期，即 3 ms；新去抖窗的实物可靠性和端到端延迟尚无新验收结论。

**MIDI 模块：**仓库已有 `code/rtl/input/midi_input/midi_input.sv` 和 `midi_event_parser.sv`。前者组合 31.25 kbaud UART 接收与解析器，后者当前只生成 Note On/Off 事件，支持零力度 Note On 转 Note Off，并有本地 FIFO、错误计数和反压接口。其默认本地 FIFO 深度为 8。**文件存在不等于正式顶层已接入；Pitch/Mod/Sustain 到音频效果的完整链路尚未完成。**

依据 D030，已购键盘型号明确为 **MIDIPLUS X4 III**。仓库硬件事实文件记录的官方能力为 49 键力度、Pitch/Mod 触控条、DIN MIDI OUT、SUS 与 EXP；本次未独立重新核验厂商资料或实物。

| 演奏控制 | 最新方案 | 待完成验证 |
|---|---|---|
| 琴键位置 | 选音、触发与和弦 | 不能重复计作额外表情维度 |
| Velocity | 力度动态；三维表情之一 | 实际值域、幅度映射与可听效果 |
| Pitch Bend | 滑音/弯音；三维表情之一 | 实际消息、回中和 FCW 调制 |
| Modulation | LFO 颤音深度；三维表情之一 | 是否为 CC1、值域和可听颤音 |
| SUS 延音 | 钢琴主模式额外表情 | 是否为 CC64、踏板极性、延音与松踏无挂音；半踏未确认 |
| EXP / 弱音踏板 | 可选扩展，不是近期满足三维指标的必购物料 | 设备支持、实际控制编号和值域 |

电子钢琴主模式以琴键和延音为核心，Pitch/Mod 默认关闭，在拓展展示模式启用。D030 已修订 D029 的“力度、延音、弱音”三维规划。T036 仍为待开始，不得把官方能力写成项目实测成果。

目标接入是 **DIN MIDI OUT → MIDI 电流环接收 → 光耦隔离与 3.3 V 逻辑整形 → FPGA**。接收电路、Bank 电压和正式输入引脚仍须确认；不能将 DIN MIDI 或未知 5 V 信号直接接入 GPIO。

### 3.3 统一演奏事件

唯一公共定义在 `code/rtl/common/audio_defs_pkg.sv`，结构保持 64 位：

```systemverilog
typedef struct packed {
    logic [2:0]  event_type;
    logic [3:0]  source_id;
    logic [3:0]  channel;
    logic [6:0]  note_number;
    logic [9:0]  velocity;
    logic [9:0]  expression;
    logic [7:0]  control_id;
    logic [11:0] control_value;
    logic [5:0]  reserved;
} performance_event_t;
```

- 握手为 `event_valid && event_ready`；未完成握手前保持有效数据。
- MIDI 7 位力度扩展为 10 位；零力度 Note On 在输入适配层转换为 Note Off。
- Pitch Bend 公共值为 12 位有符号补码，中心为 0，默认范围为 ±2 半音。
- `CTRL_PITCH_BEND`、`CTRL_MODULATION` 已定义；Sustain 若需新增编码，仍须走接口变更流程。
- 已定义事件类型不代表所有输入解析、算法消费者和顶层路径均已实现。

### 3.4 缓存、仲裁与事件 FIFO

| 对象 | 当前情况 |
|---|---|
| 按键适配器本地 FIFO | 已实现，默认深度 4，正式顶层未覆盖这一参数 |
| MIDI 适配器本地 FIFO | 模块默认深度 8，当前未接入正式顶层 |
| 公共音频事件 FIFO | 规范要求深度 32、反压、水位和溢出计数；当前正式顶层没有这一独立级 |
| 多输入仲裁 | 按键与 MIDI 的正式仲裁仍需集成和验收 |

本地缓存不能直接当作已经完成公共 FIFO。规范要求不能静默丢失 Note Off；现有本地溢出计数只能提供可观测性，完整异常恢复和挂音测试仍需在正式链路验证。

### 3.5 声部管理

`code/model/voice_manager.py` 已有 Python 分配模型，重复音符采用原槽重新触发。正式目标为保底 4 复音；声部释放、重复音、抢占与多源匹配须按统一事件和 ADSR 协同验证。

当前 `simple_voice.sv` 只保存一个活动音符，不能作为 4 声部实现。T010 在最新看板中仍为待开始；T033 声部扩展同样尚未验收。

### 3.6 音高、DDS 与波表

| 对象 | 当前实现与限制 |
|---|---|
| 音高转换 | `code/rtl/common/note_pitch.sv` 已供占位音源使用，正式算法验收归 T004 相关工作 |
| 单声部 | `simple_voice.sv` 在 `sample_tick` 下推进相位，采用正弦表，输出左右相同 PCM |
| 顶层波表 | 默认 256 点、16 位，来自 `sine_table.svh` |
| Python 波表 | 模型侧有 1024 点生成流程；正式 ROM 单一真值来源仍需统一 |
| 幅度工作点 | 16 位表峰值 8192，左移 8 位得到单声部 24 位 PCM 峰值 2097152 |

现有占位音源未根据 Velocity 实现动态幅度，也没有 ADSR。旧版本有按键瞬间咔哒声记录；后续需用包络与实测验证改善，不能提前宣称消除。

### 3.7 ADSR 包络

`code/model/adsr.py`、`adsr_sweep.py` 已存在；目标是 Attack/Decay/Sustain/Release 的时间、曲线和定点映射，并处理 Note Off 后的释放。正式 ADSR RTL 未接入顶层，T009 尚未验收。模型文件和演示结果不等于硬件包络已生效。

### 3.8 混音与饱和限幅

| 项目 | v1.2 / D028 基线 |
|---|---|
| 声部样本 | 24 位有符号 PCM，单声部峰值 2097152 |
| 累加器 | 至少 32 位；26/27 位数学下界不能替代正式实现要求 |
| 输出范围 | 饱和到 [-8388608, 8388607]，禁止回绕 |
| 正向临界 | 4 × 2097152 = 8388608，应输出 8388607 并置削波标志 |
| Python 模型 | `mixer.py`；V0064 记录上述临界计算正确 |
| RTL 与任务 | 正式混音链路尚未完成，T023/T024 待开始 |

`rtl_verifier.py` 的失败退出码与削波标志比对存在 P0 返工项。现有 1000 组参考向量的模型重算通过，不能写为“混音器 RTL 逐样本比较通过”。

### 3.9 延迟效果与音色扩展

`delay_effect.py` 与音色演示生成脚本已存在；T027 第二音色、T028 延迟效果器尚未正式验收，顶层没有对应链路。计划采用循环缓冲、干湿混合和受限反馈；48 kHz 下 500 ms 对应 24000 个样本，实际声道数、存储位宽和资源预算需结合实现确定。

### 3.10 PCM 与音频串行输出

| 项目 | 规范或实际行为 |
|---|---|
| PCM | 左右各 24 位有符号补码 |
| 目标握手 | `pcm_valid/pcm_ready`，每个采样周期最多交付一组 |
| 当前骨架 | 顶层把 `i2s_tx.valid` 固定为 1，`ready` 未用于上游节拍控制；不是完整算法流水线握手 |
| DAC 格式 | PT8211-S 使用 LSBJ 右对齐，MSB first；不是 Philips 标准 I2S 相位 |
| 帧结构 | 48 kHz，双声道，每声道 32 BCLK，每帧 64 BCLK |
| BCLK | 3.072 MHz，系统时钟下相位累加产生 |
| 位宽转换 | `i2s_tx.sv` 的 `round_saturate()` 完成 24 位到 16 位舍入与饱和 |
| BCLK 步进 | `I2S_BCLK_PHASE_STEP = 527765581`，按 2 × BCLK 翻转率计算 |

最新公共包自检已经纠正旧期望值。顶层部分历史注释仍写旧步进 `263882791`，本文按实际公共包和修正后的自检取值。欠载时保持上一样本及 `audio_underrun` 统计是正式接口要求，当前系统级欠载计数尚未完成。

### 3.11 UART 状态与诊断工程

| 对象 | 当前成果 | 验证边界 |
|---|---|---|
| 正式系统状态通道 T025 | 顶层 `uart_tx` 恒高；系统计数器与状态行尚未实现 | 不能宣称可读取正式音频状态 |
| 通用 UART | `uart_tx.sv`、`uart_rx.sv` 已有独立模块和诊断用途 | 不等于已集成 T025 |
| RX 诊断 T053 | `uart_rx_probe.sv` | V0058 已用 115200 8N1 激励确认 V14 接收路径，L6；不等于 MIDI 输入验收 |
| 外部回传 T054 | `uart_echo_probe.sv`、`echo_fifo.sv` | 仿真、工具链、下载及报告通道有证据；外部 CH340 字节级闭环仍未完成 |
| 上位机 T026 | 模拟数据、状态解析、CLI/GUI、CSV | V0066：指定解释器后 14 项软件测试 PASS，真实 COM 与 FPGA 状态流未验收 |

T025 应按接口基线落实 `active_voice_count`、`clip_count`、FIFO 水位/溢出、音频欠载、处理周期等观测信息。上位机当前候选 `STAT` 协议不能代替 FPGA 侧协议冻结。M3 仍需修复默认 Python 查找、串口依赖、异常测试和 GUI 参数校验。

### 3.12 复音数自证测试模式

T052 为正式验收关键项，目前仅有 Python 参考数据，目标 FPGA 测试模式未完成。V0064 记录离线参考数据可见 200/400/600/800 Hz 四个谱峰；这不是四复音硬件已经实现的证据。

最终需同时交付：固定 N 路纯正弦的实时 RTL 输出、N 个独立 FFT 谱峰、活跃声部和削波等观测、源码证明，以及非预录播放说明。四复音和后续扩展均以实测能力为准。

## 4. 板级硬件与引脚

平台为 Tang Mega 60K + NEO Dock，正式顶层注明器件 `GW5AT-LV60PG484AC1/I0`，IDE 封装 PBG484A、Device Version B。正式音频链为 PT8211-S → NS4263；已有耳机发声记录，具体插座与输出接法按板级事实文件核对。

### 4.1 当前正式工程约束

| 信号 | 球位 | IO 标准 / 电压 | 用途 |
|---|---|---|---|
| `sys_clk` | V22 | LVCMOS33 / 3.3 V | 50 MHz 晶振 |
| `sys_rst_n` | AA13 | LVCMOS15 / 1.5 V | 低有效复位 |
| `key_n[0]` | AB13 | LVCMOS15 / 1.5 V | A4 输入 |
| `key_n[1]` | Y12 | LVCMOS15 / 1.5 V | C5 输入 |
| `i2s_bclk` | Y17 | LVCMOS33 / 3.3 V | DAC BCK |
| `i2s_lrck` | AB17 | LVCMOS33 / 3.3 V | DAC WS |
| `i2s_din` | AA16 | LVCMOS33 / 3.3 V | DAC DIN |
| `pa_en` | AB16 | LVCMOS33 / 3.3 V | 低有效功放使能 |
| `uart_tx` | U15 | LVCMOS33 / 3.3 V | 当前正式顶层为空闲高 |

`pa_en=0` 开功放，`pa_en=1` 关功放；当前由 `~rst_sync_n` 驱动。复位/按键为 1.5 V 域，不能把所有 GPIO 都当作 3.3 V。DAC 线路输出不能直接驱动无源扬声器。

### 4.2 外部输入诊断边界

- T053 已实测 V14 为本板 UART RX，按 LVCMOS33 / 3.3 V 配置可接收；但正式 CST 中禁用项尚未解除，不能据诊断结果擅自改正式顶层。
- 板载接口可能持续驱动 V14，外部输入诊断采用 R17；它不是已冻结的正式 MIDI 输入引脚。
- T054 诊断约束采用 R17 输入、R18/T18 回传，3.3 V。V0060 更正了连接器资料：R17 对应 J14 第 5 脚或 J9 第 8 脚；地为 J14 第 12 脚或 J9 第 3/4 脚。**J14 第 11 脚是 5 V，不能当地线。**实物方向与通断仍须核对。
- 本板 J9/J8 不能套用 Digilent 通用 PMOD 排针定义。上述是诊断工程资料，不代表正式 MIDI 光耦链已经上板。
