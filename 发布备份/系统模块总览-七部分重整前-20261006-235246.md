## 1. 系统总览

FPGA 原生合成演奏音频，电脑承担开发、参考模型、采集与观测。正式核心已有四声部、DDS/ADSR、力度、混音、CC64 和真实 STAT；正式顶层已启用Program0 V1/1三角动态选择。Pitch/Mod、效果器、面板与音画新组合仍属分别验证的候选。

### 1.1 硬件连接拓扑

下图按实际设备和接口展示演奏输入、开发调试、供电、板载音频输出与显示候选之间的连接；彩色线表示信号或供电关系，不是等比例接线图。可查看[可编辑 SVG](项目硬件连接拓扑图.svg)和[接线明细及依据](项目硬件连接拓扑图.md)。

![高云杯电子琴项目硬件连接拓扑图](项目硬件连接拓扑图.png)

X4 III 的 DIN MIDI OUT 经 U187 光耦隔离后，由白线 UART_TX 接 FPGA `midi_rx`（R17；J9-8 / J14-5，31250 baud、8N1）。U187 红线使用稳定 5 V，黑线与底板逻辑侧共地；DIN 电流环不可直接接 GPIO。正式音频由板载 PT8211-S DAC、NS4263 功放送至 Speaker / 耳机接口。电脑负责 USB/JTAG 下载、UART 状态观测及开发期 USB MIDI 采集，不承担正式音频合成。底板供电方式需按实际配置选择；HDMI 仍属独立显示候选，完整音画联调未验收。

**138K迁移边界（2026-10-06）：** 本图保留60K已记录连接，不是138K可直接照接的施工图。138K L已L5、尚无L6；M3须确认实际板型、Dock、Bank/电平与接线。本文不自行将旧R17/J9/J14映射批准为138K接线。

### 1.2 当前正式顶层的实际通路

```text
板载按键 -> 同步/去抖 -> 按键事件本地 FIFO
X4 III DIN -> 隔离整形 -> R17 -> MIDI 字节/事件解析及本地调度
  -> 双源轮转仲裁 + 32 项公共事件 FIFO
  -> polyphonic_event_router + voice_allocator_4 + sustain_controller
  -> 四槽 DDS/V1 波表 + ADSR + 力度定标
  -> 双声道四路 PCM24 混音/饱和
  -> 请求代次/结果保持 -> pcm_frame_buffer
  -> i2s_tx（PT8211 16 位 LSBJ，WS 低右/高左）-> DAC/功放

完整输出帧边界 -> frame_tick -> sample_req / req_id -> 一组 PCM 结果
真实活跃数/削波/队列/欠载/耗时 -> UART STAT -> U15 -> 上位机/CSV
SOURCE_MODE=1 保留固定测试音诊断路径与 DIAG
```

`polyphonic_audio_core`模块的`DYNAMIC_TIMBRE_ENABLE`默认仍为0，但正式`electronic_piano_top`已显式传入1。Program0选择V1、Program1选择三角，按来源/通道保存，在下一次NoteOn锁槽；旧音不跟随，其他程序号忽略。V0184正式数字/L5通过，尚无新L6。

### 1.3 目标完整通路

在已实现的四声部和运行时音色选择基础上，逐步加入实际表情 FCW 消费、可选效果和音画集成。T052 独立正弦自证与报告材料单独推进。更大复音数仍需真实资源、吞吐及时序证明。

### 1.4 文档组织与接口标记

按“工具链→FPGA 公共基础→输入→事件处理→合成→混音/效果→PCM/串行→状态/显示→硬件”组织。每个模块列职责、流程、接口、代码、状态、术语和文件作用。路径相对于源码仓库；现有端口与规划接口分别标明。60K正式回退音频为50MHz，138K L候选为40MHz、48kHz音频；视频候选另有像素/串行域，使用 CDC。

**输入输出格式定义**

| 接口 / 数据 | 格式、含义与边界 |
|---|---|
| 串口输入 | 115200 baud、8N1；按完整文本行解释，串口超时不等于收到一条合法状态。 |
| 文本协议 | `STAT key=value ...`；七个键必须齐全、唯一且无未知键，键的顺序可变。数值接受十进制或 `0x` 前缀十六进制。 |
| Python 接口 | `parse_status_line(line: str) -> StatusSnapshot`；非法输入抛出 `StatusParseError`，各值限制为 uint32。 |
| 一致性约束 | `event_fifo_level <= event_fifo_high_watermark`；解析器验证格式及此关系，不凭文本判断音频是否真实可闻。 |
| CSV 输出 | `timestamp_utc` 后跟下文七个状态字段；时间为电脑记录时间，不是 FPGA 采样时刻。 |
| 诊断输入 | `DIAG` 不满足 `STAT` 前缀；不能把诊断占位值补零后当正式数据。 |

**设计流程与交接约束**

示例完整行如下，空格分隔键值，等号连接键和值；GUI 与 CLI 应使用同一解析结果，避免两套字段定义漂移。

```text
STAT active_voice_count=4 clip_count=0 event_fifo_level=2 event_fifo_high_watermark=8 event_fifo_overflow=0 audio_underrun=0 max_processing_cycles=900
```

先区分端口打不开、串口断开、行格式错误和硬件报告错误，再定位故障；“能显示数值”只证明采集路径工作。七字段的量纲和计数范围见本节末表。

**术语与概念解释**

| 名词 / 概念 | 含义与注意事项 |
|---|---|
| 状态快照 | 上报时刻的一组字段，不是逐拍波形。 |
| CSV | 状态日志表格；与 MIDI 消息 CSV 的采集对象不同。 |

#### 七个状态字段的含义

`uint32` 范围为 0～4,294,967,295；计数类字段按实现饱和，复位清零。

| 字段 | 含义 | 使用方法与边界 |
|---|---|---|
| `active_voice_count` | 当前占用的声部槽数，正式核心 0～4。 | 含仍占用的 Release/延音槽，不必等于按住的琴键数，也不能单独证明可闻频谱。 |
| `clip_count` | 混音结果执行饱和限幅且成功提交时的累计次数。 | 左右同时削波只计一组 PCM；保持/重试不重复计数。PCM24 超过 +8388607 被限幅。 |
| `event_fifo_level` | 公共演奏事件队列当前积压。 | 统计事件，不是音频样本；接近深度 32 表示处理压力。 |
| `event_fifo_high_watermark` | 复位后公共队列的历史最高水位。 | 当前为 0、最高为 12 表示曾积压 12 项。 |
| `event_fifo_overflow` | 输入本地事件丢失计数的饱和汇总。 | 不应只理解为公共 FIFO 的满标志；丢失 NoteOff 可能挂音。 |
| `audio_underrun` | 开始播放后缺少及时有效 PCM 的帧数。 | 逐缺样帧加 1 并保持上一组样本；首个有效样本前静音不计入。 |
| `max_processing_cycles` | 有效请求到成功提交的最大周期数。 | 50 MHz 一拍 20 ns，900 拍=18 μs；48 kHz 帧约 20.83 μs。新请求取消旧代次；不是 MIDI 到模拟输出总延迟。 |

例如 `4、0、2、8、0、0、900` 表示四槽占用、两项积压、最高八项，未记录削波/溢出/欠载，处理峰值 18 μs。正常演奏模式已有真实 STAT；固定测试音诊断模式仍可输出 DIAG，不应将后者视为七字段完整数据。

**输入输出格式定义**

| 接口 / 数据 | 格式、含义与边界 |
|---|---|
| 音高输入 | `midi_note_to_freq(note, a4_hz)`、`freq_to_fcw(...)` 等函数；音符号 0～127，项目采样基线 48000 Hz。 |

**设计流程与交接约束**

先锁定与 DUT 一致的 ROM、采样率和初始相位，再施加相同事件序列。算法模型通常按“一个音频样本一步”运行，不自动模拟 50 MHz 下的背压、取消或流水线延迟；这些事务行为需由专门 RTL testbench 覆盖。已有误差上限只适用于记录注明的版本和比较路径，不应对所有模型统一放宽容差。

**术语与概念解释**

| 名词 / 概念 | 含义与注意事项 |
|---|---|
| 黄金模型 | 明确数学与定点规则的参考实现，不能只与同一段错误代码互证。 |
| Q1.15 | 以 32768 为单位缩放，32767 约等于 1；容差需要按量纲解释。 |
| 位精确模型 | 在对应运算点采用相同位宽、符号和截断方式；浮点波形相似不等于定点结果一致。 |
| 样本索引 | 序列中的第几个采样点；必须先对齐启动延迟，再判断幅度误差。 |
| 容差 | 允许的最大偏差，单位可以是包络整数 LSB 或 PCM 整数 LSB，不能混用。 |
| 模型 WAV | Python 计算样本保存的声音文件，可试听算法；不包含 FPGA 实物电气链路证据。 |

**输入输出格式定义**

| 接口 / 数据 | 格式、含义与边界 |
|---|---|
| 频率换算 | `f = 440 × 2^((note−69)/12)`；32 位采样相位采用 `FCW=round(f×2^32/48000)`，A4 约 39370534。 |
| ROM 内容 | N 个有符号整数；16 位负数在 HEX/MEM 中按 16 位补码表示，例如 −1 为 `FFFF`，零为 `0000`。 |
| 地址与深度 | 1024 点使用 10 位地址；256 点使用 8 位地址。四组 256 点表还需要表组选择。 |

| 清单输出 | 参数、生成文件及哈希；修改 ROM 内容后需同步身份信息，否则“相同源码”可能读到不同声音数据。 |

**设计流程与交接约束**

波表描述一周期波形，FCW 决定读取相位每个采样推进多少。相位累加并回绕，高位选择 ROM 地址；表深影响相位量化，幅度影响混音余量。生成器是离线工具，不在 FPGA 上实时计算三角函数；测试向量还应包含输入条件、预期样本顺序和边界场景。

**术语与概念解释**

| 名词 / 概念 | 含义与注意事项 |
|---|---|
| 波表 | 存一周期的离散幅度；表有 256/1024 点不表示采样率。 |
| FCW | 每个音频采样的相位步长；A4 440 Hz 约为 39370534。 |
| 相位回绕 | 32 位相位加法绕过最大值回到低位，不保证新表索引恰好为 0。 |
| 带限谐波表 | 高音减少谐波以控制超过奈奎斯特频率的分量；并非所有瞬态都无混叠。 |
| manifest | 生成参数和文件哈希清单；源码、ROM 与构建身份应一致。 |
| ROM / MEM / HEX | ROM 是查表存储；MEM/HEX 是初始化文本文件，其行数和每行位宽须匹配声明。 |
| 补码 | 有符号整数的位编码；读取 `FFFF` 时按 16 位解释为 −1，不能按正数 65535 混音。 |
| 相位高位寻址 | 32 位相位截取高位作为地址；低位继续累加，保留细粒度音高分辨率。 |
| SHA-256 | 文件内容指纹，用于确认本次仿真/构建读取的 ROM 身份，不代表该内容已经通过算法验收。 |

|---|---|

| LSB 误差 | 样本整数相差的最小量化单位；PCM24 的 1 LSB 与 DAC16 的 1 LSB 不等量。 |

**术语与概念解释**

| 名词 / 概念 | 含义与注意事项 |

| 软件 Pitch / 线缆 Pitch | 软件 signed 值中心 0；线缆 14 位无符号值中心 8192，两种表示相差 8192。 |
| 队列与心跳 | 队列跨线程交接数据；心跳表明线程有活动，不是键盘消息完整性或时延保证。 |

### 3.1 公共基础：时钟、复位与顶层集成

#### 3.1.1 系统时钟与复位

| 项目 | 内容 |
|---|---|
| 模块职责 / 介绍 | 提供音频主域时钟和可靠复位。 |
| 设计要点 / 流程 | 50 MHz 晶振→异步拉低/同步释放；音频时序用使能，视频候选单独跨域。 |

| 当前状态 | 正式音频单系统时钟域；音画候选增加 25/125 MHz 域，约束和 CDC 必须来自对应工程。 |

**模块设计框图**

```mermaid
flowchart TD
    A["50 MHz sys_clk"] --> C["reset_sync：本域同步链"]
    B["外部低有效 sys_rst_n"] --> C
    C --> D["rst_sync_n → 音频系统逻辑"]
    D --> E["功放复位时关闭"]
    A --> F["SDC：20 ns 系统时钟约束"]
```

**输入输出格式定义**

| 接口 / 数据 | 格式、含义与边界 |
|---|---|
| 时钟 | `sys_clk` 为 50 MHz，周期 20 ns；正式音频算术和事件逻辑在该域运行。 |
| 外部复位 | `reset_sync.rst_n` 低有效，异步拉低清同步链；不是经过按键去抖的普通演奏事件。 |
| 内部复位 | `rst_sync_n` 默认经过 `STAGES=2` 同步释放；下游具体采用同步还是异步断言，以模块 always_ff 敏感表为准。 |
| 功放控制 | 顶层 `pa_en` 低有效，复位阶段关闭；恢复后按顶层逻辑使能。 |
| 候选视频时钟 | 25/125 MHz 属独立候选的像素/串行时钟，必须分别约束和复位同步，不能借用音频单域结论。 |

**设计流程与交接约束**

异步输入复位可立即让同步链进入复位；撤销后等待系统时钟逐级传播，再让本域恢复运行。所有采样脉冲仍是 50 MHz 域的一拍使能，不应当作新时钟驱动普通逻辑。复位链降低撤销时的亚稳态传播风险，不会代替跨域数据握手。

**术语与概念解释**

| 名词 / 概念 | 含义与注意事项 |
|---|---|
| 同步释放 | 复位撤销经本域寄存器，避免各状态机不同拍恢复。 |
| 时钟使能 | 只决定寄存器本拍是否更新，不产生新时钟。 |
| `rst_n` | 后缀 n 表示低有效；0 进入复位，1 允许运行，不能仅按信号名推断异步/同步。 |
| 异步断言 | 不等待时钟沿即可置入复位；解除时仍需按目标域同步。 |
| 两级同步链 | 用两个或更多寄存器逐级传递异步状态，降低亚稳态向功能逻辑传播的概率。 |
| 时钟域 | 由同一时钟采样的一组逻辑；50 MHz 与像素时钟之间即使来自同一板卡也不能裸跨总线。 |

#### 3.1.2 采样节拍发生器

| 项目 | 内容 |

**模块设计框图**

```mermaid
flowchart TD
    A["sys_clk / 相位步长"] --> B["独立 sample_tick_gen：32 位相位累加"]
    B --> C["进位 → 一拍 sample_tick"]
```

**输入输出格式定义**

| 接口 / 数据 | 格式、含义与边界 |
|---|---|
| 独立发生器输入 | `clk`、低有效 `rst_n`；参数 `ACC_BITS=32`、`PHASE_STEP=4123169`，输出单拍 `sample_tick`。 |
| 数学格式 | 平均节拍率约为 `50_000_000 × PHASE_STEP / 2^32`，默认约 48000.004608 Hz。 |
| 正式音频时基 | 以 `i2s_tx.frame_tick` 为完整双声道帧边界，由帧缓存产生 `sample_req/sample_req_id`；不能把另一个自由运行节拍当作同一时刻。 |
| 使用条件 | 消费者在时钟上升沿且使能为 1 时推进一个样本；该脉冲没有独立时钟引脚或异步握手语义。 |

**设计流程与交接约束**

分数分频通过长短整数间隔取得目标平均频率。48 kHz 在 50 MHz 下不是整数分频，不能要求每帧固定相同拍数；必须以实际帧边界作为截止期限。独立节拍工具保留用于模块验证，正式交付链路用帧请求协调采样、结果和播放。

**术语与概念解释**

| 名词 / 概念 | 含义与注意事项 |
|---|---|
| frame_tick | 输出一组左右声道完成的帧边界。 |
| 请求代次 | 每组样本的身份，防止超期旧结果被下一帧误收。 |
| 相位累加进位 | 累加超过位宽时产生一次进位，用它作为节拍；不是把累加值直接当音频幅度。 |
| 分数分频 | 交替采用邻近整数时钟间隔，使长期平均频率接近目标，单次间隔仍有一拍量级变化。 |
| `frame_tick` | 完整左右声道音频帧边界，不能与视频 `frame_start` 或单声道 WS 半帧混淆。 |
| 截止期限 | 本次样本必须在播放所需边界前可用；平均计算够快不保证最坏帧不欠载。 |

| 顶层例化 | 把模块实例与真实端口连接；文件存在或独立自检通过不等于已进入正式工程。 |
| 参数覆盖 | 顶层显式传值可改变子模块默认行为，例如动态音色使能；审阅时必须看实例参数。 |

外部 DIN 电流环必须先隔离并确认逻辑侧电平，不能直接接 FPGA GPIO。模块只生成事件，音色选择、延音行为、弯音和颤音由下游消费事件后实现；图中的输入解析能力不等于这些音频效果均已验收。

**输入格式：物理串行帧与 MIDI 消息**

输入为 31250 baud、8N1：空闲高电平，1 位低电平起始位、8 位数据（bit 0 先发送）、1 位高电平停止位，无校验位。50 MHz 下每位 1600 拍，每字节约 320 μs；包含状态字节的三字节消息约 960 μs，尚未计入后续处理和音频输出延迟。

MIDI 状态字节的最高位为 1，普通数据字节的最高位为 0，数据值范围为 0～127。对 `80`～`EF` 的通道状态字节，高 4 位表示消息类型、低 4 位 `n` 表示通道。`n` 是占位符，取十六进制 `0～F`，对应用户所见的通道 1～16；系统消息 `F0`～`FF` 不按这一通道规则解释。

```text
状态字节：bit 7              bit 4  bit 3              bit 0
          ┌─────────────────────┬────────────────────────┐
          │ 高 4 位：消息类型   │ 低 4 位 n：通道 0～15 │
          └─────────────────────┴────────────────────────┘
0x92 =      1001                  0010
            Note On              编码 2 → 用户通道 3
```

下表字节均为十六进制；`note`、`velocity`、`value` 和 `program` 均为 7 位数据。

| 输入格式 | 含义与实例 | 本模块处理 |
|---|---|---|
| `8n note velocity` | Note Off；`80 3C 00`：通道 1 释放音符 60（C4） | 输出 Note Off，保留音符与释放力度映射值。 |
| `9n note velocity` | Note On；`90 3C 64`：通道 1 按下 C4，力度为十进制 100 | 非零力度输出 Note On；力度 0 转为 Note Off。 |
| `Bn 40 value` | CC64 延音；`B0 40 7F`：通道 1 的 CC64=127 | 输出 `EVENT_CONTROL_CHANGE` / `CTRL_SUSTAIN=6`；原值 ≥64 表示开启。 |
| `Bn 01 value` | CC1 调制；`B0 01 7F`：调制值 127 | 输出 `EVENT_CONTROL_CHANGE` / `CTRL_MODULATION=1`，进入连续控制槽。 |
| `Cn program` | Program Change；`C0 01`：通道 1 选择程序号 1 | 输出 `EVENT_CONTROL_CHANGE` / `CTRL_VOICE_SELECT=5`；原样保留 0～127，不加 1、不缩放。 |
| `En LSB MSB` | Pitch Bend；`E0 00 40`：原始 14 位值 8192，处于中心 | 原值为 `LSB + 128 × MSB`；映射为 12 位补码 −2048～2047，中心为 0，输出 `EVENT_PITCH_BEND` / `CTRL_PITCH_BEND=0`。 |

`3C`=60、`64`=100、`40`=64、`7F`=127。例如 `90 3C 64` 与 `92 3C 64` 只有通道不同，分别属于用户通道 1 和 3。

Running Status 允许连续同类通道消息省略重复状态字节，例如 `90 3C 64 40 50` 表示两个 Note On。`F8`～`FF` 可穿插而不破坏半条消息；本模块不使用其内容。其他 CC、触后压力和 SysEx 等不生成上述演奏事件，但仍按消息长度消费或跳过，以维持后续解析对齐。坏 UART 帧会清除未完成的解析上下文。

**输出格式：统一 64 位演奏事件**

`event_data` 使用公共包 `audio_defs_pkg::performance_event_t`；位区间由 packed struct 的声明顺序确定，首字段位于高位。它是 FPGA 内部并行总线，不是直接发送到串口的 8 字节报文。

| 字段 | 位区间 / 位宽 | 定义 |
|---|---|---|
| `event_type` | `[63:61]` / 3 | 本模块输出 Note On=0、Note Off=1、Pitch Bend=3、Control Change=4。 |
| `source_id` | `[60:57]` / 4 | 输入来源标识，由实例参数 `SOURCE_ID` 指定；当前正式 MIDI 实例为 0。 |
| `channel` | `[56:53]` / 4 | MIDI 通道编码 0～15，对应用户通道 1～16。 |
| `note_number` | `[52:46]` / 7 | MIDI 音符编号 0～127；非音符事件为 0。 |
| `velocity` | `[45:36]` / 10 | 音符力度由 `{v[6:0], v[6:4]}` 扩展，0～1023；控制事件为 0。 |
| `expression` | `[35:26]` / 10 | 公共事件预留的表情字段；本模块当前输出 0。 |
| `control_id` | `[25:18]` / 8 | 公共控制编号：Pitch=0、Modulation=1、Voice Select=5、Sustain=6；不是 MIDI 原始 CC 编号。 |
| `control_value` | `[17:6]` / 12 | Pitch 使用有符号补码；CC1/CC64 按 `{v[6:0], v[6:2]}` 扩展为 0～4095；Program 为零扩展的 0～127。 |
| `reserved` | `[5:0]` / 6 | 保留位，置 0。 |

音符事件的 `control_id/control_value` 均为 0。CC64 的 12 位阈值为 2048，对应原始 MIDI 值 64；输入模块传递数值，具体延音状态由下游控制器维护。

**模块端口、参数与交接约束**

| 端口 | 方向 / 位宽 | 定义 |
|---|---|---|
| `clk`、`rst_n` | 输入 / 各 1 | 系统时钟；低有效同步复位。 |
| `midi_rx_async` | 输入 / 1 | 隔离后的异步串行输入，在 `uart_rx` 内同步。 |

| `event_fifo_overflow_count` | 输出 / 32 | 离散 FIFO 无可用空间时丢弃新事件的次数。 |
| `midi_rx_busy` | 输出 / 1 | UART 正在接收一帧。 |

默认参数为 `CLK_HZ=50_000_000`、`MIDI_BAUD=31_250`、`LOCAL_FIFO_DEPTH=8`、`SOURCE_ID=0`、`MAX_DISCRETE_BURST=8`。错误计数均饱和于 `0xFFFFFFFF`，复位清零。正式顶层目前接出了 MIDI 溢出计数，其他本地诊断端口未全部接入系统状态输出；公共 FIFO 的状态水位不等于本模块的本地水位。

`event_valid=1` 且 `event_ready=0` 时，当前事件保持稳定。离散 FIFO 保持 Note、CC64 和 Program 之间的到达顺序；Pitch/CC1 则合并未发送的更新、轮转选择并限速，**不保证与离散事件之间的严格原始到达顺序**。默认的 8 次上界只在连续控制已有待发值且冷却结束时成立，并按成功的离散握手计数；下游长期背压时不承诺固定时间内送达。FIFO 深度表示缓存容量，不表示支持的复音数。

**设计流程与交接约束**

两个适配器复用相同事件构造函数，但输入性质不同：板载键只有开关边沿，无法测击键速度，因此采用固定配置力度；MIDI 键盘已有力度测量。零力度 NoteOn 在公共队列前转为 NoteOff，避免下游创建无声但仍占用的声部。多键同拍可能产生多项，须按实现顺序入队并对丢失数饱和累计。

**术语与概念解释**

| 名词 / 概念 | 含义与注意事项 |
|---|---|
| Velocity | 起音力度，不直接等于最终音量；经增益表和包络转换。 |
| 饱和计数 | 达到最大值后保持，避免回绕掩盖错误。 |
| Note Number | MIDI 音高编号，例如 60 为项目约定的 C4；不是 FPGA 槽号或 GPIO 编号。 |

**设计流程与交接约束**

两源同时有效时依据轮转优先级选一源，成功入队后把优先权让给另一源。公共队列通过反压阻止过量写入，真正无法暂停的外部输入由本地队列吸收；本地仍满时才可能丢事件。STAT 的 overflow 来自输入侧丢失汇总，不能把公共“满”直接当“已丢失”。

**术语与概念解释**

| 名词 / 概念 | 含义与注意事项 |
|---|---|
| 合并 | 未发送的同一来源/通道控制只保留最新值，NoteOff 不采用此规则。 |
| 公平性 | 持续 Note 流不能无限饿死已就绪控制事件。 |
| 两级 FIFO | 本地队列吸收不可反压串口，公共队列统一调度；深度不等于复音数。 |
| Round-robin | 在竞争输入间轮流分配机会；仅在成功传输时推进，避免反压期间虚假消耗优先权。 |
| 同拍出入队 | 读出旧队首并写入新事件可发生在同一沿；占用数按入队减出队更新。 |
| 水位 / 满 / 溢出 | 水位是存量，满表示没有闲位，溢出表示新事件实际丢失；三者不能互换。 |
| 32 槽控制轮转 | MIDI 内部选择通道控制项的调度，与外层按键/MIDI 两源轮转是两级不同仲裁。 |

| 联合身份匹配 | source、channel、note 全部一致才是同一音符，单独比较 note 会误释放其他输入。 |
| `slot_valid` | 本次分配结果有效的通知，不能当“该槽永久发声”的状态位。 |

#### 3.4.2 音高查表与 FCW

| 项目 | 内容 |

| 模块职责 / 介绍 | 把 MIDI 音符号转换成采样域相位步长。 |

| 输入输出 / 接口定义 | note_number→phase_step/FCW，正式 DDS 每音频采样推进一次。 |
| 代码位置 | `code/rtl/common/note_pitch.sv`、`code/model/dds_model.py` |
| 当前状态 | 基础音高已进入四声部；不能混用 50 MHz 固定测试音 FCW 与 48 kHz 采样 FCW。 |

**模块设计框图**

```mermaid
flowchart LR
    A["note_number 7 位"] --> B["半音索引 note % 12"]
    B --> C["C4 八度的 12 项 FCW 常量表"]
    A --> D["相对 C4 八度偏移"]
    C --> E["左移 / 右移 → phase_step 32 位"]
    D --> E
```

**输入输出格式定义**

| 接口 / 数据 | 格式、含义与边界 |
|---|---|
| 输入 | `note_number[6:0]`，0～127；69 为 A4，60 为 C4。 |
| 输出 | `phase_step[ACC_BITS-1:0]`，默认 32 位无符号，表示每个音频采样的相位增量。 |
| 参考关系 | `f=440×2^((note−69)/12)`，`FCW≈round(f×2^32/48000)`；A4=39370534。 |
| 实现形式 | 组合查 12 项预计算表，按八度作整数移位；移位量化与逐音符直接浮点舍入不必逐 LSB 相同。 |
| 参数限制 | `SAMPLE_RATE_HZ` 用于语义说明，表为固定常量，修改该参数不会自动重算表；换采样率须重新核定常量。 |

**设计流程与交接约束**

FCW 增大时相位每采样前进更多，音高升高；增加一个八度等价于步长翻倍。此模块没有时钟/ready 端口，消费者应在正确采样/音符锁存时点使用组合输出。32 位步长属于 48 kHz 音频采样口径，不能用于每个 50 MHz 时钟都更新相位的振荡器。

**术语与概念解释**

| 名词 / 概念 | 含义与注意事项 |
|---|---|
| 半音/音分 | 十二平均律相邻半音频率比 2^(1/12)，一半音 100 音分。 |
| 奈奎斯特频率 | 48 kHz 采样的一半为 24 kHz，谐波超出会折返混叠。 |
| `FCW` / `phase_step` | Frequency Control Word，即每次推进相位加上的整数；它不是频率 Hz 的直接整数值。 |
| 八度 | 频率翻倍为升高一八度，对应 MIDI 编号加 12；数字步长通常左移一位。 |
| 组合查表 | 输入改变后经组合路径得到结果，没有输出有效脉冲；时序收敛仍取决于后级锁存路径。 |
| 量化音高误差 | FCW 只能取整数，低音移位舍弃低位会产生很小的频率偏差，需按实际表核对。 |

| 名词 / 概念 | 含义与注意事项 |

| LFO | 低频振荡器，这里用于周期调制音高；5 Hz 表示每秒约五次变化，不是可闻基音。 |
| Portamento | 从一个音高按时间连续滑向另一个音高，需要独立目标与过渡规则，不能把所有弯音都称为此功能。 |

**模块设计框图**

```mermaid
flowchart TD
    A["采样使能锁存 PCM / dry / wet / feedback"] --> B["环形 RAM 读取旧历史 d"]
    A --> C["dry × x"]
    B --> D["wet × d"]
    C --> E["各乘积先右移 15 → 相加饱和 → pcm_out"]
    D --> E
    B --> F["feedback × d → 右移 15"]
    F --> G["加当前输入 x → 饱和 → 写回 RAM"]
    G --> B
```

**输入输出格式定义**

| 接口 / 数据 | 格式、含义与边界 |
|---|---|
| 算法输入 | `pcm_in` signed24、`sample_enable`；低有效异步断言复位，50 MHz 时钟，按音频采样使能锁定输入和参数。 |
| 控制参数 | `delay_samples[15:0]`；`dry_gain/wet_gain/feedback[14:0]` 为无符号 Q0.15，范围 0～32767。 |
| 算法输出 | `pcm_out` signed24，`pcm_valid` 为结果有效；算法路径 E 接受、E+2 输出，不带下游 ready。 |
| 存储地址 | `rd_ptr=(wr_ptr−delay_samples低地址位) mod DEPTH`，DEPTH 为 2 的幂；delay=0 读到上一整圈同地址旧值。 |
| 事务候选 G | request/result 各自 valid/ready，携带 id32、单路 PCM24 和锁存参数；单在途并支持取消排空。 |

**设计流程与交接约束**

设 x 为当前输入、d 为读出的历史样本，Q(g,s)=floor(g×s/32768)，则 `输出=sat24(Q(dry,x)+Q(wet,d))`，`写回=sat24(x+Q(feedback,d))`。两项乘积先分别截断，再相加，不能先求和后统一移位。声音结束后继续输入零样本推进历史以保留尾音；cancel 不回滚已接受输入的历史，reset 才清除历史。

**术语与概念解释**

| 名词 | 解释 |
|---|---|
| 干湿比 | 原声 dry 与历史回声 wet 的增益组合；Q0.15 最大 32767，略小于 1。 |
| 反馈 | 将历史样本按增益写回环形缓存，形成多次回声；必须做饱和和边界验证。 |
| delay=0 | 当前合同表示整 DEPTH 圈旧历史，不是真零延迟或旁路；默认 1024 点/48 kHz 为约 21.333 ms。 |
| 尾音 | 所有声部释放后仍可能有缓存回声，需要继续输入零样本推进，不能立刻清空效果。 |
| 取消与复位 | cancel 只取消事务可见结果，保留已接受样本对历史的影响；reset 清历史，二者不可混用。 |
| mono effect | 当前候选效果只处理一路混音再复制左右，不能称独立立体声效果。 |
| 环形缓存 | 固定容量 RAM 的地址到末端后回绕；写指针表示当前历史位置，不代表无限音频存储。 |
| Q0.15 | 增益整数除以 32768，32767 约等于 0.99997；最大值不是精确 1。 |
| 延迟容量 | N 点在 48 kHz 下约为 N/48000 秒；1024 点约 21.333 ms，不能宣传为 500 ms。 |
| 单在途事务 | 前一次请求未完成/排空前不接受下一次；ready 表示真实接受能力，不是算法采样脉冲。 |

**输入输出格式定义**

| 接口 / 数据 | 格式、含义与边界 |
|---|---|
| 请求 | `sample_req` 单拍、`sample_req_id[31:0]`；frame_tick 推进代次，仅 calc_ready 时发请求。 |

| 计数 | frame/request/commit/underrun 各 uint32；请求 id 用于代次识别，与饱和统计计数用途不同。 |

**设计流程与交接约束**

frame_tick 分支优先建立新一代请求并消费已提交样本；同一边界的迟到数据不能偷渡为新代次。未拿到第一组有效播放数据前输出静音；开始播放后若边界缺样，保持上一组并累计欠载。左右、clip 与 id 必须整体保存，背压时不能只保持样本而让标志或身份变化。

**术语与概念解释**

| 名词 / 概念 | 含义与注意事项 |
|---|---|
| 原子提交 | 左右声道及 clip 属于同一请求，不能分别更新。 |
| 欠载保持 | 缺样重复上一有效帧；缺少首个有效样本时保持静音。 |
| `req_id` | 样本计算事务的 32 位代次，区分新请求与迟到结果；不是 MIDI 音符身份。 |
| pending / held | pending 是已收到但等待播放边界的数据，held 是最近实际保持的播放样本。 |
| 欠载 | 播放需要新样本时没有及时有效结果；保持上一样本可维持串行时序，但声音仍可能失真。 |
| 取消旧代次 | 新帧到来后旧计算结果不再拥有提交资格，防止迟到的样本错配到下一帧。 |

**输入输出格式定义**

| 接口 / 数据 | 格式、含义与边界 |
|---|---|
| PCM 输入 | `valid`、signed24 `pcm_left/right`；内部同组锁存，不能在左右半帧之间更换成不同请求。 |
| 位宽转换 | `biased=sign_extend(pcm)+128`，`shifted=biased >>> 8`，再限幅至 −32768～32767；中间保留 25 位避免正端进位溢出。 |
| DAC 样本编码 | 16 位补码，`0000`=0、`7FFF`=32767、`8000`=−32768；按 MSB 先发送。 |
| 物理帧 | 64 个 BCLK 为一双声道帧，每声道占 32 个 BCLK；有效样本在半帧后 16 位，LSB 对齐末端。 |
| 引脚时序 | BCLK 约 3.072 MHz、WS 约 48 kHz；WS 低=右、高=左，DIN 在下降沿更新，DAC 上升沿采样。 |
| 交付脉冲 | `frame_tick` 表示完整帧边界；`ready` 保留直接输入旧语义，不能用它替代 PCM 帧缓存的事务 ready。 |

**设计流程与交接约束**

加 128 后右移是当前指定舍入口径，恰好半 LSB 的负数也按该公式处理，不应另换成“远离零舍入”。LSBJ 的对齐判定必须以物理 WS 翻转和采样沿为准；不要因模块名叫 i2s_tx 就采用 Philips I2S 的延一位规则。BCLK 是输出时序，内部状态仍由 50 MHz 和使能推进。

**术语与概念解释**

| 名词 / 概念 | 含义与注意事项 |
|---|---|
| LSBJ | 最低有效位与半帧末端对齐的格式，不能按 Philips I2S 延一位解码。 |
| 物理 WS 边界 | 以实际引脚翻转确定左右半帧，不能用复位后的内部计数猜测。 |
| MSB / LSB | 分别是最高/最低有效位；UART 数据通常 LSB 先传，本 DAC 音频样本按 MSB 先传，不能混用。 |
| 半帧 / 完整帧 | 半帧只含一个声道，完整帧包括左右两声道；48 kHz 表示每秒左右样本组数。 |
| 舍入偏置 | 转 PCM24 到 PCM16 前加半个目标 LSB（128），改善截断误差；之后仍必须饱和。 |
| 右对齐 | 有效字的最低位靠半帧末端，前面空余位不属于额外音频精度。 |

**输入输出格式定义**

| 接口 / 数据 | 格式、含义与边界 |
|---|---|
| 键盘消息 | NoteOn/Off、Velocity、Pitch、CC1、CC64 和可配置 Program；每种实际输出需按设备设置与抓包核实。 |
| DIN 链路 | 标准 MIDI 电流环到 U187 DIN INPUT；不直接连接 FPGA GPIO。 |
| U187 逻辑侧 | 白线 UART_TX → R17（J9-8/J14-5）；黑线 → GND（J9-3/4 或 J14-12）；红线稳定 5 V，黄色 UART_RX 当前不接。 |

**设计流程与交接约束**

先核对 U187 接口和电平，再用逻辑分析仪对照操作采集原始字节，最后用同版正式码流验证听感/状态。U187 自带其他功能不代表本项目依赖其合成音频，正式声音由 FPGA 生成。输入能发某控制消息只证明消息源存在，不证明下游音频算法已接入。

**术语与概念解释**

| 名词 / 概念 | 含义与注意事项 |
|---|---|
| 隔离整形 | 将 MIDI 电流环转换为适合 FPGA 的逻辑信号；核对极性/3.3 V 电平。 |
| 半踏 | 连续踏板位置对应连续效果；当前 CC64 使用二值阈值，未实现半踏。 |
| DIN OUT / DIN INPUT | 键盘发送口与模块接收口的方向关系，OUT 应连对端 INPUT；不是两路都接 FPGA 的输出。 |
| Grove 线色 | 当前 U187 文档约定红电源、黑地、白 TX、黄 RX；以实物型号和资料核实，不能套用于任意模块。 |

| 逻辑侧共地 | U187 UART 输出与 FPGA 要有共同电压参考；不能据此旁路 DIN 侧光耦隔离。 |

## 5. 系统级接口与接线索引

### 5.1 层间接口

| 层间 | 接口/现状 |
|---|---|
| 输入→事件 | 64 位 valid/ready；本地 FIFO 与公共 32 项 FIFO |
| 事件→声部 | 联合身份、槽代次、CC64 释放握手；不接收任意未实现控制作为音频效果 |
| 声部→PCM | 四槽波形/包络→Q15 增益→PCM24→32 位累加/24 位饱和 |
| PCM→DAC | 同请求代次/原子左右提交→16 位 LSBJ，WS 低右/高左 |
| 状态→电脑 | 正常模式七字段 STAT；固定测试音可用 DIAG |
| 事件→显示 | 副本/CDC；独立音画候选，不阻塞音频 |

### 5.2 当前正式工程引脚

| 信号 | 球位 | IO 标准 / 电压 | 用途 |
|---|---|---|---|
| `sys_clk` | V22 | LVCMOS33 / 3.3 V | 50 MHz 晶振 |
| `sys_rst_n` | AA13 | LVCMOS15 / 1.5 V | 低有效复位 |
| `key_n[0]` | AB13 | LVCMOS15 / 1.5 V | A4 输入 |
| `key_n[1]` | Y12 | LVCMOS15 / 1.5 V | C5 输入 |
| `i2s_bclk` | Y17 | LVCMOS33 / 3.3 V | DAC BCK |
| `i2s_lrck` | AB17 | LVCMOS33 / 3.3 V | DAC WS |
| `i2s_din` | AA16 | LVCMOS33 / 3.3 V | DAC DIN |
| `pa_en` | AB16 | LVCMOS33 / 3.3 V | 低有效功放使能 |
| `midi_rx` | R17 | LVCMOS33 / 3.3 V，PULL=UP | MIDI 隔离整形后的 31250 baud 输入 |
| `uart_tx` | U15 | LVCMOS33 / 3.3 V | 正常模式 STAT / 固定测试音 DIAG |

`pa_en=0` 开功放，`pa_en=1` 关功放；当前由 `~rst_sync_n` 驱动。复位/按键为 1.5 V 域，不能把所有 GPIO 都当作 3.3 V。DAC 线路输出不能直接驱动无源扬声器。

### 5.3 外部输入诊断边界

正式 MIDI 使用 R17，V14 仍不作为外接 MIDI 输入。诊断 R18/T18 不占正式 top。R17 对应 J14 第 5 脚或 J9 第 8 脚，地为 J14 第 12 脚或 J9 第 3/4 脚；J14 第 11 脚是 5 V，不能作地。实物连接仍应核对方向、电平和原理图；上述引脚表仅覆盖正式音频工程，不替代 HDMI 候选约束。
